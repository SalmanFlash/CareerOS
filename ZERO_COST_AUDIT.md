# Local milestone cost audit

| Component used | Operation | Billing required | Data and limits |
| --- | --- | --- | --- |
| Flutter SDK and Dart | Local compilation and UI | No | Uses installed tools and free packages. |
| Node.js | Local preview and offline packaging | No | Preview server binds to 127.0.0.1. |
| Browser storage and service worker | Missions, preferences and offline shell | No | Saved in the current profile. Storage availability and retention depend on browser settings. |
| GitHub / LinkedIn guidance | Local outlines, draft editing and manual clipboard copy | No | No API, sign-in, model, posting service or credentials. Drafts remain in browser storage and encrypted backups; copying is user-triggered. Offline guides remain available. |
| Greenhouse Job Board API | User-triggered and twice-daily scheduled public GET requests for five employer boards | No | No API key, account, application submission or private mission data. Browser requests time out after 12 seconds (scheduled collector: 20 seconds) and failed boards retain their last successful timestamp. |
| Local Gmail scanner | Read-only Gmail requests with the owner's Desktop app OAuth client | No billing is provisioned | Requires user setup and university permission. Runs every 15 minutes while the local service is on. Real account authorization remains unverified. |
| Windows DPAPI | Encrypt local OAuth credentials and short mail excerpts | No | Bound to the current Windows account. Ciphertext is stored outside the repository and excluded from Git. |
| GitHub Pages and standard public Actions runner | Build and serve the static phone preview | No | Public repository, standard Ubuntu runner, no paid services. Only compiled frontend assets are uploaded, retained for one day. Local Gmail service and data are excluded. |

The public listing endpoints and authentication rules are documented in the [Greenhouse Job Board API](https://docs.greenhouse.io/job-board). Live availability depends on each employer keeping its board public.

GitHub documents [Pages availability for public repositories on GitHub Free](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) and [free standard runners in public repositories](https://docs.github.com/en/billing/concepts/product-billing/github-actions). The workflow is limited to this public repository and does not select larger runners or enable billing.

The local build uses deterministic guidance and local email parsing. No paid model, analytics integration or paid fallback is configured. Independent Gmail requires the owner's OAuth configuration. Verify permissions and quota behavior against the actual account before treating the connection as ready.

## Scheduled public snapshot (26 November 2026)
Verified against the linked GitHub billing/schedule and Greenhouse API documentation: standard public Ubuntu runners remain free; public GETs need no key. Existing public-only workflow guard retained. Two best-effort runs daily (03:23/15:23 UTC), plus authorized pushes/manual builds; 15-minute job cap, 20-second request cap and 4 MiB per-response cap, five sequential board GETs and one previous-snapshot GET per build. Output is only public listing ID/title/location/source/URL/timestamps; no mail, mission notes, OAuth credentials or browser data. No account billing/card configuration or paid fallback. Artifact retention remains one day and the uncompressed upload is capped at 64 MiB. Artifact storage shares the account's included allowance with Packages; this is not unlimited storage. No paid overage is enabled by this project. With no payment method, quota exhaustion blocks uploads; retain manual checks rather than add billing. Scheduled jobs can be delayed/missed and disable after 60 days of repo inactivity; the app retains manual checks and shows actual per-board timestamps.
References: [Actions pricing](https://docs.github.com/en/billing/concepts/product-billing/github-actions), [schedule limits](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule), [public Job Board API](https://docs.greenhouse.io/job-board.html).

## CERN summer research source (26 November 2026)
Provider: CERN public postings hosted by SmartRecruiters. No account, API key, OAuth, billing/card, application submission or paid fallback. Unauthenticated PUBLIC GET was verified against the real source; both original listing links returned HTTP 200. Uses at most five sequential pages of 100 postings, bounded by 12-second browser or 20-second collector requests and 4 MiB per response. Failed/incomplete/duplicate pages preserve prior results and timestamps. Existing twice-daily public Actions schedule and artifact caps apply; the collector now makes five Greenhouse GETs, up to five CERN GETs and one prior-snapshot GET. No private data is sent. Source failure reduces coverage without switching to a paid API.
Only the two summer student families are selected. Other CERN programmes have different nationality/education restrictions and are not presented as eligible. Individual student eligibility, funding and deadlines require the original listing; removal dates are not application deadlines.
References: [Posting API](https://developers.smartrecruiters.com/docs/posting-api), [public list endpoint and pagination](https://developers.smartrecruiters.com/reference/v1listpostings), [CERN summer programme](https://careers.cern/programmes/summer-studentship/).
